## 这个节点负责什么

“角色”节点负责建立玩家会遇到的人物。基础画像决定玩家能认出谁，深层设定帮助故事在不同场面保持同一个人的性格和说话方式，分幕目标则说明这个角色在某一段故事里想推动什么。

雾港来信的主要角色示例是**林舟**：他是潮汐邮局的夜班管理员，知道一部分来信经过，但不会在第一次见面时直接说出全部真相。

## 基础画像

| 字段 | 作用 | 示例 | 玩家在哪里看到 |
| --- | --- | --- | --- |
| 姓名 | 给角色一个稳定、易辨认的称呼 | `林舟` | 对话气泡、角色菜单和角色详情 |
| 身份 | 说明角色和当前故事的关系 | `潮汐邮局的夜班管理员` | 玩家打开角色详情时看到，也会影响角色介绍方式 |
| 性别 | 补充角色资料；不需要时可以不预设 | `男` | 角色详情中的资料项（填写后才显示） |
| 年龄 | 让人物资料和叙事保持一致 | `32` | 角色详情中的资料项 |
| 分幕立绘 | 为不同阶段准备不同图片 | 第一幕穿深色工作外套，旧码头一幕被海风吹乱衣领 | 场景中的角色立绘、对话旁头像和角色详情图片 |

玩家可以从游戏菜单的**角色**页查看已出现的角色，也可以点击对话旁的角色头像打开详情。姓名、年龄、性别和身份会以资料项显示；有图片时，立绘会出现在对话、场景或详情面板中。没有填写的资料不会被强行补出来。

### 基础画像的填写方法

- 姓名要前后一致，不要在不同幕里随意换称呼；
- 身份写玩家能理解的关系，不要写作者才看得懂的内部简称；
- 年龄要和角色经历、说话方式相互匹配；
- 立绘只在角色的状态或时间确实发生变化时分幕设置，不要为了“每幕一张”而重复上传。

## 深层设定

这些字段是后台设定。玩家不会在角色详情里直接看到“核心欲望”或“破防后说话方式”，但会从角色的选择、行动、对白和压力下的反应感受到它们。

| 字段 | 应该写什么 | 示例 |
| --- | --- | --- |
| 核心欲望 | 角色最想得到或守住的东西 | `守住邮局里一份不能公开的寄件记录` |
| 底线与破防点 | 什么事情会让角色拒绝、失控或改变立场 | `不接受别人把未寄出的信直接烧掉` |
| 常用手段 | 角色平时解决问题的方式 | `先确认对方看到了什么，再只回答一个问题` |
| 外在人设 | 角色平常留给别人的印象 | `安静、礼貌，总在整理桌面` |
| 外在说话方式 | 角色平时的句子长度、语气和习惯 | `句子短，回答前会先看一眼门口` |
| 压力下本性 | 被逼到紧张时最先暴露的反应 | `会先把寄件记录压在手下，再解释自己的动机` |
| 破防后说话方式 | 失去平常控制后，语言如何变化 | `开始直接说出“潮水最高前必须离开”` |

写深层设定时，优先写**可观察的表现**。例如不要只写“他很勇敢”，而要写“危险靠近时仍然先把身后的人推到安全处”。这样角色才会在游玩中被玩家认识，而不是停留在作者说明里。

## 各幕目标

在**各幕目标**里，为角色填写他在每一幕想完成的事情，例如：

> `在“潮汐前的邮局”确认沈遥是否看见潮痕，并决定要不要交出旧码头的钥匙。`

各幕目标是后台字段，不会作为目标清单直接显示给玩家。它会帮助角色在同一幕的不同对话中保持方向：玩家可以用不同方式交流，但角色不会无缘无故忘记自己要解决的问题。

## 从角色字段到游玩页面

可以用下面这条线检查填写是否有效：

1. **姓名、身份、年龄、性别**让玩家在角色菜单里认出这个人；
2. **立绘**让玩家在场景和对白旁看到这个人；
3. **深层设定**通过角色的对白、行动和压力反应表现出来；
4. 如果角色绑定了可见的[状态组件](/create/editor/status)，玩家打开角色详情时还能看到状态名称和当前数值；
5. 角色在某一幕能不能出现，还要回到[幕](/create/editor/act)中绑定，不要只创建角色节点却没有接入任何幕。

## 完成检查

- 姓名和年龄已经填写；
- 玩家需要辨认的资料没有互相矛盾；
- 深层设定写的是行为和反应，不是空泛形容词；
- 角色已经绑定到实际会发生故事的幕；
- 至少在一次测试中从角色菜单和对话头像检查过展示效果。
