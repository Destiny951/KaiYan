## 这个节点负责什么

“剧本起点”是玩家第一次认识作品的地方，也决定故事从哪一幕开始。它不是一段普通简介：列表和详情需要给玩家看的内容，要和后台用来约束整部作品的内容分开填写。

本章示例统一使用虚构剧本**雾港来信**：玩家扮演沈遥，在潮汐邮局收到一封写给自己的未寄信件。下面的示例值都围绕这条故事线展开。

## 剧情设定页

| 字段 | 作用 | 示例 | 玩家在哪里看到 |
| --- | --- | --- | --- |
| 剧本名称 | 给作品一个清楚、好辨认的名字 | `雾港来信` | 剧本列表、详情页和游戏入口 |
| 是否为系列剧本 | 决定作品是独立游玩，还是按章节归入系列 | 选择“独立剧本” | 详情页的作品类型和系列信息 |
| 主流程连接 | 指定起点之后进入的第一个幕 | 连接到“潮汐前的邮局” | 不显示设置本身，玩家直接从连接的幕开始 |
| 剧本简介 | 用一两段话告诉玩家这是什么故事 | `你在潮汐邮局收到一封写给自己的未寄信件。潮水正在上涨，地址却指向旧码头。` | 剧本列表和详情页 |
| 标签 | 帮玩家按题材或气质筛选 | `悬疑`、`现代` | 剧本卡片和筛选区 |
| 剧本语言 | 约束故事主要使用的语言 | `简体中文` | 不显示设置文字，影响游玩时的演出语言 |
| 封面 | 让玩家在列表中快速认出作品 | 一张潮汐邮局夜景图 | 剧本列表、详情页和管理卡片 |
| 剧本总览 | 从六个角度概括整部作品 | `现代悬疑短篇；从邮局收到来信，追查到旧码头，最后完成回信。` | 不直接展示，帮助整部故事保持方向一致 |
| 剧本总控 | 规定玩家回应、演出边界、推进等待和收束方式 | `只承认玩家明确行动；线索先于情报；确认身份并完成回信后收束。` | 不直接展示，影响故事怎样回应玩家 |

### 剧本简介怎么写

只写玩家在开始前应该知道的前提、地点、问题和吸引点。不要在这里塞入作者笔记、幕后答案或一整套写作要求。

推荐结构：

> 你是谁 → 现在在哪里 → 面前有什么问题 → 玩家可以期待怎样的体验。

以“雾港来信”为例：

> 你在潮汐邮局收到一封写给自己的未寄信件。潮水正在上涨，信上的地址却指向今晚仍然亮着灯的旧码头。你需要在潮水最高之前弄清楚，谁把信留在这里。

### 剧本总览的六层写法

把长文分成六段，每段回答一个问题：

1. **作品定位**：这是一部什么题材、什么规模的故事？
2. **开局情景**：玩家第一次出现在哪里，眼前有什么事实？
3. **核心命题**：这部作品真正想让玩家面对什么问题？
4. **整体气质**：节奏、距离感、情绪和语言大致是什么样？
5. **叙事弧线**：从最初的未知到结尾，事实怎样逐步改变？
6. **结局落点**：故事结束时兑现什么，哪些事情不要擅自延伸？

每层写两三句话即可。先说明事实和方向，再留出玩家行动的空间。

### 剧本总控的四层写法

1. **玩家回应处理**：哪些输入算作玩家明确说过或做过的事？不要替玩家补写没有选择的台词、承诺和关键行动。
2. **演出边界**：人物、地点、物品、时间和危险的边界是什么？哪些事实不能凭空增加？
3. **剧情推进与等待**：什么事情完成后才进入下一阶段，哪些关键行动必须等玩家来做？
4. **自由度与收束**：哪些路线可以变化，最后在什么事实成立时进入结局？

这四段写给后台演出使用，不要写成对玩家说的宣传文案。

## 故事背景页

故事背景会在玩家点击“开始新游戏”后，以阅读页分页展示。它负责让玩家知道人物、地点、当前状况和初始问题；它不是开场对白，也不是幕后设定。

建议每页只放一到两段完整内容。换页要有理由：例如从环境转到人物，再转到眼前的问题。不要把关键答案提前全部写完，也不要在背景页直接让玩家做选择。

以“雾港来信”为例：

- 第 1 页：沈遥在停电的潮汐邮局醒来，潮声正在靠近；
- 第 2 页：桌上有一封写给沈遥的信，信封边缘留着盐痕；
- 第 3 页：林舟握着旧码头的钥匙，潮水最高前必须做出决定。

## 开场设计页

开场设计包含两类玩家可见内容：**开场文本设计**和**开场推荐行动**。故事背景读完后，开场文本会按顺序播放；推荐行动只在新游戏的开场阶段展示一次，玩家可以参考，也可以自己输入。

### 开场文本怎么拆

每一条文本只承担一个动作或一个信息：

- **旁白**：地点、动作、声音和可以被观察到的事实；
- **角色**：角色此时说出的台词；
- **内容**：真正展示给玩家的文字。

示例：

| 说话者 | 内容 |
| --- | --- |
| 旁白 | `应急灯在你面前亮起，信封边缘的盐痕像刚被潮水吻过。` |
| 角色 | `“这封信不是今晚登记的。”` |
| 旁白 | `林舟把通往旧码头的钥匙压在掌心。` |

开场只呈现已经发生的事实。不要在这里替玩家写“你决定调查”或“你感到害怕”，把第一次决定留给玩家。

### 推荐行动怎么写

行动风格是按钮的短标签，行动文案是玩家可以直接点选的完整动作。例如：

| 行动风格 | 行动文案 |
| --- | --- |
| 观察 | `查看信封上的收件人和潮痕。` |
| 询问 | `问林舟：旧码头今晚还有谁会去？` |

推荐行动应该帮助玩家理解当前可以做什么，而不是替玩家决定故事答案。点击推荐后会直接作为本回合输入，因此文案要写成完整、可执行的行动。

## 主角设定页

主角选择决定玩家进入故事时扮演谁。主角应当与角色节点建立清楚关系；玩家姓名模式则决定新游戏时使用剧本预设姓名，还是让玩家自己输入。

常用设置建议：

- **主角**：选择一个真正由玩家控制的角色，不要把旁观者或幕后人物设为主角；
- **叙事视角**：统一整部作品的叙述方式，例如使用“你”来描述玩家；
- **主角名模式**：如果作品依赖固定身份，使用剧本自设；如果希望玩家代入，选择让玩家自定义，并写好名称提示。

雾港来信可以选择角色节点“沈遥”作为主角，使用“剧本自设”保留这个名字；如果希望玩家代入，也可以让玩家自定义姓名，提示写成“你希望别人怎样称呼你？”。玩家实际看到的是主角在故事中的称呼、行动空间和相关演出，不是这些设置项的原文。

## 完成起点后的检查

- 简介单独拿出来看，玩家在列表里能否知道故事卖点；
- 背景读完后，玩家是否知道自己在哪里、面前有什么问题；
- 开场是否只展示已经发生的事实；
- 推荐行动是否真的能在当前场景执行；
- 起点是否连接到恰好一个幕；
- 主角是否已经选择，主角和普通角色的关系没有混淆。

填完后点击**保存**，再进入[幕](/create/editor/act)和其他节点。
